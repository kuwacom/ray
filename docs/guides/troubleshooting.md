# 困ったとき

## 読み込みが遅い

設定を 1 つ変えたとき、R キーで再読み込みしたとき、ディメンションを移ったときは、Iris がパイプラインを全部作り直します  
時間の大半はプログラムのリンクで、Iris は 1 本ずつ順にコンパイルとリンクをするので、いちばん重いリンクがそのまま全体の時間に乗ります

NVIDIA のドライバはシェーダーをディスクにキャッシュします  
キャッシュに当たるのはソースの文字列がまったく同じときだけで、コメント 1 文字の違いでも外れます  
そのため次のようになります

- 初めて読み込むとき、パックを更新した後、ドライバを更新した後はキャッシュがなく遅くなります  
  同じ設定なら 2 回目から速くなります
- 設定を変えて本文が変わると、その設定を読むプログラムだけが作り直しになります
- ON/OFF や方式の選択は本文を変えるので、作り直しになります  
  ボクセル範囲 (`VOXEL_VOLUME`) は全部のプログラムに入っているので、変えると全部作り直しです
- 強さ・倍率・距離を決めるだけの設定は本文を変えないので、キャッシュに当たって速く済みます  
  フォグの濃さ・光芒の強さ・太陽の明るさ・露出補正・ボケの量・マニュアルフォーカスの距離・フォーカスの速さ・HDR モード・シャッター速度・ISO・F 値がそうです

スイッチと方式を先に決めてから値を詰めると、待つ回数が減ります

毎回遅いときは、次の順に見ます

1. 同じ設定のまま、もう一度読み込み直します  
   2 回目が速ければキャッシュは効いています
2. 速くならなければ、NVIDIA コントロールパネルの「シェーダーキャッシュのサイズ」が小さすぎないか、無効になっていないかを見ます
3. キャッシュのフォルダは、Windows ではふつう `%LOCALAPPDATA%\NVIDIA` の下の `GLCache` です  
   消すと次の読み込みは全部作り直しで遅くなるので、不具合を切り分けるとき以外は消さずにおきます

## 縞・ざらつき・ノイズ

| 見え方 | よくある原因 | 直し方 |
|---|---|---|
| 金属やつやのある面に斜めの縞、模様の細かい面のざらつき | 自動法線が強すぎる | 「自動法線の強さ」を下げる ([materials.md](materials.md)) |
| たいまつの影がざらつく・ちらつく | 光源トレースのサンプル不足 | 「ノイズ除去」を「時間 + 空間」に、「1 ピクセルあたりの光源数」か「トレース解像度」を上げる ([block-light.md](block-light.md)) |
| 光源の多い床に、照り返しの切り替わる線 | 鏡面反射の光源数が少ない | 「鏡面反射の光源数」を上げる |
| 光源が密集した場所でちらつく | ビンの上限 (64 個) を超えて、毎フレーム別の光源が外れる | 「上限を超えた時の光源の選び方」を「明るさ x 近さ」に、「ビンごとの光源の上限」を上げる (重くなる) |
| 弱い光源の周りに光の円の縁 | 光の届く距離が「レベル」 | 「光の量」にする ([block-light.md](block-light.md)) |
| GI にまだらが残る、止まっているとちらつく | GI のノイズ除去が足りない | 「GI のノイズ除去」を「時間 + 空間」に、「GI の履歴の長さ」か「GI のサンプル数」を上げる ([shadows-gi.md](shadows-gi.md)) |
| 振り向いた直後に GI がまだら | 履歴が短い所 | 「新しく見えた所の GI のぼかし」を上げる |
| 太陽の影の縁がざらつく | PCSS のサンプル不足 | 「影のサンプル数」を上げるか、「影のフィルタ」を PCF に |
| 粗い面の映り込みがざらつく | 粗い反射のならしが弱い | 「粗い反射のならし」を上げる (映り込みは少しぼける) |
| 雲にノイズ | 雲の品質が低い | 「雲の品質」か「雲の解像度」を上げる |
| ボケが点々や輪になる | ボケのサンプル不足 | 「被写界深度の品質」を上げる |
| 水底が画面の端で滑る | 屈折の方式が「端で弱める」 | 「ボクセルで辿る」か「波の分だけ」に ([water-reflections.md](water-reflections.md)) |

縦縞・横縞・ブロック状のノイズ・櫛のようなずれ・ドロップアウトは、アナログの効果です  
「アナログ」を OFF にすると消えます ([analog.md](analog.md))

## 明るさと色

| 見え方 | よくある原因 | 直し方 |
|---|---|---|
| 画面全体が暗い / 明るい | 露出の方式と補正 | 「露出補正」を動かす、M・P・A・S なら SS・F 値・ISO で ([camera.md](camera.md)) |
| 夜が暗すぎる | 現実の光の比、夜の持ち上げ | カメラの露出なら「夜の明るさ」を上げる、自動露出なら「夜の持ち上げ」を見る |
| 夜が昼のように明るい | 現実の光の比が OFF | カメラの露出のとき `EXPOSURE_PHYSICAL_LIGHT` を ON に |
| 暗部が黒くつぶれる | 2.2 乗のモニターとのずれ | ルックを「カスタム」にして「暗部の持ち上げ」を上げる ([profiles.md](profiles.md)) |
| 日陰が青すぎる | 空の環境光の彩度が高い | 「空の環境光の彩度」を下げる |
| 日陰や白樺の幹が緑がかる | 草の照り返しの色 | GI の「空の光の照り返しの色」とルックの「照り返しの色の濃さ」を下げる |
| 洞窟の奥や横穴が暗い | 洞窟の光漏れ防止 | `CAVE_LEAK_PREVENTION` を OFF に ([sky-clouds-fog.md](sky-clouds-fog.md)) |
| 室内や洞窟の入り口が暗すぎる | 空の光の遮蔽 | 「空の光の遮蔽」を下げる |
| 明るい所が白く飛ぶ | トーンマップと露出 | 「DR の補正」か「HDR モード」を試す、夜の灯りの白飛びは測光を「評価」に |
| 色が強すぎる | ルックと LUT の重なり | 「LUT の強さ」を下げる、グレーディングを切ってルックだけで比べる |
| 画面の四隅が黒い | 魚眼の合わせ方が「横幅を合わせる」 | 「隅まで埋める」に |
| 魚眼の中央が甘い | 歪曲を final で引き伸ばしている | 「歪曲を TAA で組み立てる」を TAA か自動に (TAA を ON にしておく) |

## そのほか

- 影や GI に距離の境目が見えるとき: 影の距離をボクセル範囲の半径以上にします  
  ボクセルの GI なら「ボクセル GI のフェード幅」を上げます
- 窓越しの景色がぼけるとき: 「ガラスにピントを合わせる」を OFF にします
- 手前の水面と映り込みがぼけるとき: 「水面にピントを合わせる」を ON にします
- 長時間露光で溜めた絵が消えたとき: ウィンドウの大きさを変えると溜めた分は消えます
- 雨が降っても地面がなかなか濡れないとき: 「濡れるまでの時間」を短くします  
  雨雲とフォグも同じ速さで増え減りします

## 動作環境

- OptiFine では動きません  
  SSBO・カスタムイメージ・compute shader を使っていて、これらは Iris にしかありません
- macOS は compute shader が使えないので動きません  
  開発と動作の確認は Windows だけで行っています
- Distant Horizons には対応していません  
  入れたままでも読み込めますが、LOD の部分の見え方は保証できません
- 対応する Minecraft は 1.20.1 から 26.x までです  
  ゲームの中で確かめたのは Iris 1.7.6 + Sodium 0.5.13 (1.20.1) と Iris 1.11.x (26.1.2) で、1.21.x の Iris 1.8〜1.10 と Oculus 1.8.0 (Forge) はコンパイルとリンクの確認だけです

古い Iris (1.8 未満) と Oculus では、新しい Iris と違う所があります

- 花火の火花は不透明の粒として描くので、画素を間引いて TAA でならします  
  コマンドで色を真っ白にした花火は光りません
- エンティティの影とボクセル化に専用のパスがなく、地形と同じジオメトリシェーダーを通ります  
  自分かどうかを目の位置からの距離で決めるので、自分の体から 1.6 ブロック以内にいるほかのプレイヤーも自分として扱われます
- Oculus は雷を別の経路で光らせます
- アナログの見え方は、ゲームの中でまだ確かめていません

## デバッグ表示

「デバッグ」の「デバッグ表示」(`DEBUG_VIEW`、既定 OFF) で、内部のバッファを画面に出せます

| 値 | 見えるもの |
|---|---|
| 1 | アルベド |
| 2 | 法線 |
| 3 | ライトマップ |
| 4 | ブロックライト (直接光) |
| 5 | floodfill |
| 6 | GI / AO |
| 7 | 雲 |
| 8 | ボリューメトリック |
| 9 | SkyView LUT |
| 10 | ボクセル断面 |
| 11 | 速度ベクトル |
| 12 | デバッグイメージ |

照り返しがおかしいときは 6 で GI / AO だけを見ます  
光源の影がおかしいときは 4 と 5 を見比べると、直接光と floodfill のどちらのせいかが分かります  
法線の縞は 2 で見えます

## 不具合を報告するとき

次を書いてもらえると調べやすくなります

- 入れた zip のファイル名 (README の「導入」)
- Iris と Minecraft のバージョン
- プロファイルと、変えた設定
- ゲームのログ (`logs/latest.log`) のシェーダーのエラーの行
